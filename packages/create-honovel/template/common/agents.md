# Honovel project guide for coding agents

This project is a Honovel application generated by `create-honovel`. Read this file before changing framework-specific code.

## Project structure

- `index.ts` is the runtime entrypoint. It creates the Hono application and exports it for Cloudflare Workers.
- `src/features/<feature>/` contains feature code. Keep controllers, DTOs, actions, repositories and services close to the feature that owns them.
- `src/runtime/Controller.ts` is the application-owned controller base. It adds the `/api` prefix to feature controller routes.
- `src/database/<name>/` contains a database provider, Drizzle schemas and migrations. Keep schemas and migration history grouped by physical database.
- `frontend/` contains the optional Nuxt 4 frontend. It exists only when Nuxt was selected during project creation and uses the same origin as the API in production. API-only projects have no frontend directory, dependencies or assets configuration.
- Runtime and build helpers are provided by the `honovel` CLI from `@honovel/core`; there is no generated `scripts/` directory. `.honovel/` and `dist/` contain generated output; application code belongs in `src/`, `frontend/` and `index.ts`.

The project `README.md` describes the selected Nuxt or API-only setup. The backend is always Cloudflare Workers. Check `package.json` and `wrangler.jsonc` before changing deployment or platform code.

## Working conventions

- Import Honovel APIs from `@honovel/core` and the selected runtime package. Do not import application code from `.honovel/`.
- Use the Honovel CLI for new structure: `npm run honovel -- make:feature <name>` and the other `make:*` commands listed in `README.md`.
- Controllers handle HTTP input and delegate application work to actions or services. Repositories own database queries.
- The database schema starts empty. Add/export tables, then generate and apply migrations before using them. Run `npm run typecheck` after framework or TypeScript changes.
- Keep request-specific state scoped to the request. In Cloudflare Workers, do not store request or binding objects in module-level mutable state.

## Honovel documentation

The hosted documentation is the source of truth for framework APIs and runtime behavior:

- Index for agents: https://honovel-docs.lutze.workers.dev/llms.txt
- Complete agent documentation: https://honovel-docs.lutze.workers.dev/llms-full.txt
- Human-readable documentation: https://honovel-docs.lutze.workers.dev
- Individual Markdown topics: https://honovel-docs.lutze.workers.dev/raw/<topic>.md

When working on Honovel-specific code, consult `/llms.txt` first and load the relevant topic from `/raw/` before implementing framework APIs. Use `/llms-full.txt` when the task spans several parts of the framework or when the topic is unclear. This prevents assuming undocumented APIs from other frameworks or plain Hono.
